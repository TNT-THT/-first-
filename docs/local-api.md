# 单台电脑本机运行网页与 API（网页显卡推理）

本指南把网站和 OpenAI 兼容 API 都运行在同一台电脑上。API 只绑定 `127.0.0.1`，只有这台电脑上的浏览器和软件能访问；不需要公网域名、VPS 或第三方托管平台，也**不需要安装 Ollama**。

> **推理方式：**本机 API 不直接跑模型，而是把请求通过 WebSocket 桥接给**正在打开的本网页**，由网页里的 WebLLM（WebGPU）用显卡生成回答。网页必须保持打开；关闭网页后 API 会返回“本机模型网页尚未连接”，重新打开网页即可自动恢复。

> **为什么不能只点网页按钮就启动？** 浏览器出于安全限制，不能自己在电脑上监听端口、也不能替你启动程序，所以必须有一个一次性的“双击启动”动作把本机服务跑起来。除此之外全部在网页里完成：服务启动后浏览器会自动打开网页，你只需登录并在网页里点“申请 API Key”。

## 准备

1. **什么都不用装。** 网站包已内置 Node 运行时（`runtime/`）和服务端依赖（`server/node_modules/`），下载解压后双击即可，不需要预先安装 Node.js，也不用再联网安装组件。（只有当内置运行时在个别电脑上无法运行时，启动窗口才会提示去安装 Node.js LTS 作为后备。）
2. 用最新版 Chrome 或 Edge（桌面端）打开网页，并确认显卡驱动正常（网页需要 WebGPU）。
3. 首次使用某个模型时，网页会从 Hugging Face 下载权重并缓存在浏览器中（每个模型约几百 MB 到数 GB，取决于模型大小）；之后可离线使用。

> 仅当你在 Git 仓库里用 `npm run start:local-api` 手动启动（进阶方式）时，才需要自己安装 Node.js 18.18 或更高版本。

## 启动（新手：下载网站包，双击一次）

1. 在 GitHub Pages 网站里按你电脑的系统下载对应的网站压缩包（Windows 版 `site-win-x64.zip`、Mac Apple 芯片版 `site-darwin-arm64.zip`、Mac Intel 芯片版 `site-darwin-x64.zip`、Linux 版 `site-linux-x64.zip`，**只下你那一个**；网页会按你当前的电脑标出推荐项），**完整解压**到一个文件夹。
   每个包已内置本机 API 所需的全部内容：对应平台的 Node 运行时（`runtime/`，只有一个，不用一次下四个平台）、Node 服务端（`server/`，含运行依赖）、启动脚本（`scripts/`）、服务版网页（`web/dist-api/`）和双击启动文件。下载这一次就够了，不需要再下载或安装其他任何东西（模型权重除外，见“准备”第 3 条）。下错版本时启动器会提示，回到网站重新下对应版本即可。
2. Windows 双击 `start-windows.bat`；macOS 双击 `start-mac.command`。启动器会优先使用包内内置的 Node 运行时。
3. 黑色窗口会显示生成的「网站口令」和「管理口令」，请记下来。
   第一次启动的口令会保存到被 Git 忽略的 `.local-api.json`；若项目已有有效 `.env` 配置，则尽量沿用。服务强制绑定 `127.0.0.1`，不会向局域网或公网开放。
4. 浏览器会**自动打开** `http://127.0.0.1:3000`，用「网站口令」登录即可。之后所有操作都在网页里完成。

- 网页：`http://127.0.0.1:3000`
- API Base URL：`http://127.0.0.1:3000/v1`
- 对话接口：`http://127.0.0.1:3000/v1/chat/completions`

网页打开后会自动连上 API 桥接（网页里“API 接入”能看到连接状态和可用模型数）。使用期间不要关闭黑色窗口，也不要关闭网页；关闭黑色窗口即停止服务。电脑休眠、停止服务或关闭网页后，API 就不能生成回答，重新双击启动文件并打开网页即可恢复。

没有 Node.js 时的后备方式（只有网页聊天、没有 API）：Windows 双击 `start-windows-static.bat`；macOS / Linux 在解压目录运行 `python3 serve-site.py`。

### 进阶：在仓库里用命令启动（可选）

在项目根目录运行 `npm run start:local-api` 效果相同（缺少依赖时自动 `npm ci`、自动构建服务版网页、就绪后自动打开浏览器）。

如果 3000 端口已被占用，可设置 `LOCAL_API_PORT` 后启动，例如：

```bash
LOCAL_API_PORT=3001 npm run start:local-api
```

Windows PowerShell：

```powershell
$env:LOCAL_API_PORT = "3001"
npm run start:local-api
```

## 申请并使用 API Key（网页自助）

1. 先用首次启动时显示的网站口令 `APP_PASSWORD` 登录本机网页，再打开 **API 接入**。
2. 在 **“申请 API Key（本机网页）”** 一节点击 **“申请一把 API Key”**，完整 Key 只显示一次，请立即复制保存。点完这一步，API 就可以用了，不需要再做任何配置。
3. 在兼容 OpenAI 的客户端填写 Base URL `http://127.0.0.1:3000/v1` 和这把 Key；模型名使用网页下拉框里显示的模型 ID（例如 `Qwen2.5-3B-Instruct-q4f16_1-MLC`）。也可以先请求 `GET /v1/models` 查看当前网页提供的全部模型。

本机命令行测试示例：

```bash
curl http://127.0.0.1:3000/v1/chat/completions \
  -H 'Authorization: Bearer <API_KEY>' \
  -H 'Content-Type: application/json' \
  -d '{"model":"Qwen2.5-3B-Instruct-q4f16_1-MLC","messages":[{"role":"user","content":"你好"}],"stream":false}'
```

Windows 可在 PowerShell 中使用 `curl.exe`，或在兼容 OpenAI 的软件里填写相同地址和 Key。

## 可用模型

- 网站内置的 39 个模型（见 `web/public/config.json`）都可通过 API 调用，首次调用某个模型时网页会先下载并加载权重，耗时较长；之后调用会直接使用已加载的模型。
- **每个请求都可以选不同的模型**：API 调用时在请求里写不同的 `model` 即可（先用 `GET /v1/models` 看全部可用模型）；网页聊天顶部也有模型选择栏，选中哪个就用哪个生成。网页的选择会记在本浏览器中，API 每次请求选什么模型**不会**改掉网页的选择，反过来也一样。
- 网页聊天与 API 共用这台电脑的显卡，请求会排队逐个生成，不会互相打断；但显卡同一时间只加载一个模型，交替使用不同模型时会来回重新加载（权重下载过就不用再下，只是加载变慢），连续使用同一个模型最快。
- 已在这台电脑的同一浏览器来源中登记的“导入模型 / 新建 AI”也会出现在 `/v1/models` 中（导入记录只存在于这台电脑的浏览器里；新登记后桥接会自动同步，必要时刷新本页）。
- 同一时间只处理一个 API 请求（显卡一次只能跑一个生成），多余请求会排队；队列满时返回 429。

## 管理员（两个面板，分工不同）

- **管理员面板**（顶部按钮）：管理这台电脑浏览器里的东西——导入“新建AI”、删除导入的 AI、直接填数字修改当前模型的参数。登录后即可使用。**API 地址也显示在这个面板里**，可一键复制（`http://127.0.0.1:3000/v1`）。
- **API 管理**（顶部按钮）：用首次启动时显示的管理口令 `API_ADMIN_PASSWORD` 验证后，管理全站 API Key、调整服务端参数（temperature、输出上限等），并使用 API 调试台。若没记下管理口令，可在解压文件夹的 `.local-api.json` 中查看 `API_ADMIN_PASSWORD` 字段（找不到时请先在文件管理器中显示隐藏文件；请勿分享这个文件）。
- 普通网站口令（`APP_PASSWORD`）不能代替管理口令，也不能直接调用 `/v1`。
- GitHub Pages 的静态网页没有服务器，因此那里的“管理员面板”只能管理当前浏览器里的模型和数据，不包含本机 API 的参数控制台与全站 Key 管理；请打开本机启动后的 `http://127.0.0.1:3000` 再操作。

## 导入的 AI 也能通过 API 生成

可以。在本机网页的 **管理员面板** 中点“导入模型文件”（或“导入训练结果”）加入“新建AI”后：

- 它会自动出现在网页顶部模型栏里，网页聊天可直接选用；
- 它也会出现在 API 的 `GET /v1/models` 列表中，在请求里填它的模型 ID 即可用它生成，与内置模型用法完全相同；
- 删除导入的 AI 后，它会同时从网页模型栏和 API 模型列表中消失。

## 常见问题

- **获取模型列表报 `Cannot GET /v1/chat/completions/models`（404）：** 软件里的 Base URL 填成了完整对话接口。这类软件会自己在 Base URL 后面拼 `/models` 和 `/chat/completions`，所以 Base URL 应只填 `http://127.0.0.1:3000/v1`（到 `/v1` 为止）。服务端已兼容这种误填（拼错的路径也能取到模型列表并对话），但建议改成正确地址。
- **软件里模型名称一直没变：** 多半是模型列表没获取成功，软件保留了旧名字。先按上一条改对 Base URL，再在软件里重新获取/刷新模型列表并选用返回的模型 ID；也可以直接把模型 ID 手填为 `GET /v1/models` 返回的值（例如 `Qwen2.5-3B-Instruct-q4f16_1-MLC`）。
- **获取模型列表很慢或要等很久（开着多个服务网页标签页时）：** 模型列表由“当前提供 API 的那个标签页”上报。更新网站包后，更新前就开着的旧标签页仍是旧版代码，它会占住提供方位置并让获取/生成变慢或只报通用错误。新版服务端会自动停放这种旧标签页（前提是至少有一个最新版标签页开着）。稳妥做法：关掉所有旧的服务网页标签，只保留从最新版网站包打开的页面，并按 Ctrl+F5 刷新一次。
- **日志出现“当前提供 API 的是未上报诊断信息的旧版模型网页”：** 同上：真正干活的是没刷新过的旧标签页。关掉所有旧标签、只留最新版页面并按 Ctrl+F5；重新打开新标签页后请求会自动改由新版页面提供。
- **消息 content 是分段数组的客户端：** 已支持 OpenAI 的富文本分段格式（`[{ "type": "text", "text": "…" }]`），服务端会拼成纯文本；消息里只有图片时本机模型用不了，会明确返回 400 说明。`user`、`stream_options`、`metadata` 这类不影响生成的字段会被直接忽略，不再整单拒绝。
- **软件自带系统提示词（system）：** 可以照常带。网页引擎会把请求里的所有 system 与本站系统提示合并成开头唯一一条再交给模型，不会再出现 `SystemMessageOrderError: System prompt should always be the first message` 这类报错（该错误与模型本身、与导入是否成功无关，是消息顺序触发的模板校验）。
- **在网页应用里调用（如纸上谈兵 https://pd.geneluo.fun ）：** 这类网页由浏览器直接发请求，受跨域（CORS）与浏览器本地网络权限限制。本机版默认已把本站和 `https://pd.geneluo.fun` 放入白名单：在该站选择 OpenAI / Compatible、填 Base URL `http://127.0.0.1:3000/v1` 与你的 Key 即可；浏览器若弹出本地网络访问询问请点允许（不同浏览器支持程度不同，Chromium 系支持最好）。其他网站需在 **API 管理 → 管理员参数控制台 →「允许调用 API 的网站白名单」** 中每行添加一个来源后保存（立即生效、重启保留）。注意：只添加你信任的网站——在该网站中输入的 Key 会被它的网页代码接触到。白名单只对 `/v1` 接口生效，申请 API Key 只能在本站网页（`http://127.0.0.1:3000`）里操作，白名单网站不能替你申请 Key；通配写法至少要写到二级域名（如 `https://*.example.com`）。

## 安全和限制

- API 调用支持的生成参数：`temperature`、`max_tokens`、`top_p`、`stop`、`frequency_penalty`、`presence_penalty`、`repetition_penalty`、`seed`、`response_format`（`text` / `json_object`）；不支持的参数会直接返回 400 说明，不会静默忽略。调用方未指定 `temperature` / `max_tokens` 时，使用网页管理员面板里为该模型设置的本机参数，服务端只做总量封顶。
- 此本机模式**不会**让其他电脑通过 LAN、GitHub Pages 或互联网访问 API；`127.0.0.1` 只指向本机。服务本身也拒绝以桥接模式绑定非本机地址（确需如此须显式设置 `OJ_ALLOW_PUBLIC_BRIDGE=1` 并自行负责隔离）。
- 不要把 `.env`、`.local-api.json` 或创建的 API Key 提交到 Git，也不要把 Key 放到公开网页前端。
- 首次下载模型权重需要网络和磁盘空间；下载完成后，推理完全在本机显卡上完成，不必调用云模型 API。
- 如果只打开 `https://tnt-tht.github.io/-first-/`，那仍是 GitHub Pages 的静态版，不会连接本机 API。必须打开本机启动后的 `http://127.0.0.1:3000`（从压缩包双击启动会自动打开）。
- 若要让其他电脑访问，需要改成局域网/公网部署并配置相应的访问控制与 HTTPS；本指南刻意不开放网络监听。
