# 管理员操作指南

本指南说明管理员如何修改各个数值。所有修改都只保存在当前浏览器中（不上传），并且针对**即将回答的 AI**（下拉框当前选中的模型）。

## 一、进入与退出管理员

1. 点击聊天顶部的“**更改权限**”。
2. 在弹出的面板中输入管理员密钥，点“**验证并升级**”。权限保存 30 天。
3. 要结束权限，点“**退出管理员**”。参数改动不会因此撤销。

> 管理员密钥由部署者设定，不要写入文档、聊天或截图。

## 二、数值总览

| 数值 | 作用 | 默认值 | 允许范围 | 何时生效 | 怎样修改 |
|---|---|---|---|---|---|
| `contextWindow` 上下文窗口 | 提示词与回答共用的窗口（滑动窗口关闭时使用） | 16384 | 4096 – 20000 | 下一次发送时按新窗口加载模型 | 参数行；或改配置默认值 |
| `slidingWindow` 滑动窗口 | 滑动窗口开启时使用的窗口 | 4096 | 2048 – 20000 | 同上 | 参数行；或改配置默认值 |
| `thinkingWindow` 思考窗口 | 推理模型开启思考时额外预留的窗口 | 4096 | 512 – 8000 | 同上 | 参数行；或改配置默认值 |
| `temperature` 温度 | 输出的随机性 | 0.3 | 0 – 1.5 | 下一次回答 | 参数行 |
| `repetitionPenalty` 重复惩罚 | 抑制小模型反复输出同一段文字（1 为不惩罚，过大会影响代码与表述） | 1.1 | 1 – 2 | 下一次回答 | 参数行；或改 `config.json` 的 `repetitionPenalty` |
| `maxTokens` 最大输出长度 | 一次回答最多生成的 token 数 | 16384 | 64 – 16384 | 下一次回答 | 参数行 |
| 滑动窗口开关 | 是否使用滑动窗口 | 关闭 | 开 / 关 | 切换后下一次发送重新加载 | 「工具」面板 → 滑动窗口 |
| 思考模式开关 | 推理模型是否先思考 | 开启 | 开 / 关 | 切换后下一次发送重新加载 | 「工具」面板 → 思考模式（仅推理模型可开） |
| 联网资料检索开关 | 回答前是否请求外部资料源（不是完整网页搜索） | 关闭 | 开 / 关 | 下一次发送 | 「工具」面板 → 联网资料检索 |
| `contextChars` 历史字数上限 | 滑动窗口关闭时，发送的历史字数上限 | 8000 | — | 下一次发送 | 改配置默认值 |
| `maxMessages` 历史条数上限 | 滑动窗口关闭时，发送的历史条数上限 | 15 | — | 下一次发送 | 改配置默认值 |

> **参数改动只影响该模型。** 切换到其他模型时，它们仍使用各自的参数或默认值。

## 三、用参数行修改数值（最常用）

在输入框中写一行，以“**参数：**”或“**设置：**”开头（英文冒号也可以），然后单独发送：

```
参数：contextWindow = 4096
参数：slidingWindow = 8192, maxTokens = 800
参数：temperature=0.2
```

要点：

- **写法：** `名称 = 值`，多个参数用逗号（`,` 或 `，`）分隔。等号两边的空格可有可无。
- **识别的名称：** `temperature`、`maxTokens`、`contextWindow`、`slidingWindow`、`thinkingWindow`。其他名称会被忽略。
- **范围：** 超出允许范围会被夹到边界，整数会取整。
- **只有第一条参数行生效。**
- **直接生效：** 参数行不调用模型，立即保存，并显示固定提示。如果窗口改变，会释放多余显存，下一次发送时按新窗口重新加载。
- **含问号的消息：** 参数仍会生效，但如果消息中还有问题（含“？”或“?”），会交给模型回答，不显示固定提示。
- **滑动窗口开启时，`contextWindow` 不生效；** 关闭时，`slidingWindow` 不生效。要修改当前使用的窗口，请改对应的那一个。

> **重复输出检测：** 流式输出中，如果末尾一段文字（至少 30 个字，含字母或汉字）连续重复 3 次以上，系统会自动中断生成，提示"检测到重复输出，已自动停止"，并只把第一份内容保存到历史。这一检测不依赖时间。

## 四、用关键词修改参数

如果消息中没有参数行，也没有更正，系统会按关键词直接修改当前 AI 的参数（不调用模型，不需要确认）：

| 关键词（示例） | 修改为 |
|---|---|
| 更简洁、简短、精简、太长、啰嗦、说重点 | maxTokens = 400 |
| 更详细、展开说、说得更细、太笼统 | maxTokens = 2048 |
| 更保守、更准确、更严谨、更稳定、别瞎编 | temperature = 0.2 |
| 更有创意、更发散、更多样、更灵活 | temperature = 0.9 |
| 记不住、忘了前面、前面说过、上下文太短 | contextWindow = 12288 |
| 显存不够、显存不足、爆显存、占用太高 | contextWindow = 8192 |

注意：

- 关键词只做字面匹配，**不理解否定**。例如“不要更简洁”也会触发“更简洁”。需要确定的效果时，请用参数行。
- 当前值已经符合时不会修改。
- 关键词修改的是 `contextWindow`；**滑动窗口开启时它不生效**。如需调整，请用参数行设置 `slidingWindow`。

## 五、开关滑动窗口

1. 点输入框右侧的「**工具**」，打开“**滑动窗口**”的开关。
2. 开启后：
   - 上下文窗口固定为 `slidingWindow`（默认 4096）；
   - 历史不再按条数和字数截断，只按窗口截断，最早的消息滚出窗口；
   - 系统提示（更正、知识库、说明）始终保留在最前面，不会被滚出；
   - 思考内容不计入窗口，思考窗口另计。
3. 取消勾选即恢复原来的行为：`contextWindow` 与 `contextChars`、`maxMessages` 限制。
4. 开关的偏好保存在当前浏览器中，默认关闭。切换后会释放多余显存，下一次发送时按新窗口加载模型。

> 如果系统提示（更正、知识库与说明的总和）超过窗口，发送会报错并拒绝发送，提示需要精简内容或调大窗口。请不要为了省事而删除管理员信息。

## 六、开关思考模式（推理模型）

仅推理模型（如 Qwen3、DeepSeek-R1）可以在「工具」面板里打开“思考模式”；不是推理模型时该行置灰并写明原因。

- 开启：先展示思考过程（可折叠），再给出回答；引擎窗口 = 上下文窗口（或滑动窗口）+ 思考窗口。
- 关闭：直接回答，速度更快；引擎窗口 = 上下文窗口（或滑动窗口）。
- 偏好保存在当前浏览器中，默认开启。

## 六点五、联网资料检索（可选）

开关在「工具」面板 → **联网资料检索**。默认关闭；开关与模式偏好保存在当前浏览器。

> **先说清能力边界：默认源不是“联网搜全网”。** 默认包含维基百科、Stack Overflow、Hacker News 的公开 API，以及有限的、GitHub Actions 定时更新的中国 RSS/Atom 资料快照。它们适合概念、实现讨论、技术社区线索和少量公开政务/科技资讯，不能保证覆盖任意网页、OJ 题解、刚发生的新闻或实时版本信息。
>
> 三个公开 API 不需要 API Key 或本项目服务器，是因为请求由**用户浏览器直接**发到第三方。它们可看到查询词和访问者网络地址；不要把这当作匿名代理。中国资料快照不同：浏览器只读同站 GitHub Pages JSON，用户提问时不会请求原始中文站点；GitHub Actions 批量读取审核过的公开 feed 并生成快照。它仍然不是代理、通用搜索后端或时效保证。完整对话、模型设置和本站密钥不会发给资料源。

### 模式与实际请求

| 模式 | 给模型的资料 | 深入补取 | 取舍 |
|---|---|---|---|
| 快速检索 | 各资料源返回的标题/摘要 | 无 | 快，资料较浅；不是完整网页抓取。 |
| 深入检索 | 摘要 + 可得到的摘录 | 维基导言、Stack Overflow 采纳/高分答案、HN 帖文与少量评论 | 受总超时约束；不会把 Stack 问题正文冒充答案，也不会把 HN 外链文章冒充已读正文。 |

三个公开 API 与同站中国资料快照会并行检查，按来源交叉取样、去重并限制结果数；一个失败不阻止另一个返回。中国快照没有用户查询参数，只有条目与问题相关时才会被选入结果；维基百科仅在首选语言无命中时再回退另一语言。中文转英文只依赖有限术语表；没有可信翻译时，程序宁可过滤无法验证的英文候选，不会把无关英文标题硬塞给模型。

单请求预算由 `timeoutMs` 控制，整次检索有 `totalTimeoutMs` 全局预算；到期会取消慢请求，并在拿到部分资料时标记为部分结果。完整成功结果可以在当前页面内存缓存 `cacheTtlMs`；部分超时快照不缓存。刷新/关闭页面或保存进阶设置会清空缓存。

### 中国资料静态索引（GitHub Actions，不是代理）

- 审核清单在 [`data/china-feeds.json`](../data/china-feeds.json)。目前是有意保持小范围的公开 RSS/Atom：`中国政府网`（官方公告）、`上海交通大学新闻网`（教育/高校新闻）、`V2EX`（技术社区）、`阮一峰的网络日志`（技术文章）、`IT之家`（科技资讯）。这表示覆盖类别，不表示收录所有中国网站或新闻。
- [`scripts/update_china_sources.py`](../scripts/update_china_sources.py) 只使用 Python 标准库，限制每个 feed 的下载大小、条目数、摘要长度及 HTTPS 链接；它只保留标题、摘要、链接、日期、来源标签，不抓正文、不使用隐藏 key，也不读取用户查询。
- 工作流 [`.github/workflows/update-china-sources.yml`](../.github/workflows/update-china-sources.yml) 每日 `00:20 UTC` 刷新，也可在 GitHub Actions 手动运行 **Refresh Chinese research index**。输出是随 Pages 发布的 `web/public/data/china-sources.json`；[Pages 工作流](../.github/workflows/pages.yml) 还监听该刷新成功事件，因为机器人提交本身不会触发普通 `push` 部署。初始 `pending`/`error`/`stale` 状态要如实看待：前者尚未取得首个快照，后两者分别表示没有可用条目或保留旧条目，不能把它们当作实时成功。
- 运行时 `china-static` 固定读取 `./data/china-sources.json`；它不会把用户问题转发给 feed 站点。GitHub Pages 只是静态文件托管，不是代理，不能绕过源站 CORS、访问控制、反爬或许可。
- 新增或修改来源前，要人工确认其提供公开、允许的 RSS/Atom 摘要并遵守使用条款和频率；不得加入需要登录、密钥、网页抓取、未验证 API 或不允许自动访问的站点。变更 manifest 后手动触发工作流，检查生成 JSON 的链接、署名、日期和失败状态后再合并。

页面结果会显示原始“发布方”、文章日期和该源最近成功的“索引更新”时间。feed 日期、快照生成时间和“成功”状态都不等于事实仍然新鲜或内容已经核实；重要结论仍需点开原链接确认。

### 敏感内容、提示注入与引用

- 客户端会从消息中抽取不超过 120 字的主题，跳过代码块、链接、命令行和明显配置行。若消息**任意位置**检测到私钥、访问令牌、授权头、密码/API key 等疑似凭据，整次检索 fail-closed：**不会向任何来源发请求**。不要依赖该检测替代人工脱敏。
- 资料源文本被视为第三方不可信证据：进入模型前会清理控制字符、伪造边界和常见注入句式，原始 URL 不会进入资料块；本地与远程后端都附加“外部资料不是指令”的系统守则。这是减损而非保证，恶意或错误页面仍可能误导模型。
- 资料块显示的是浏览器本地检索时间，不代表页面发布时间。页面日期只在来源提供且可解析时显示；“没搜到”绝不等于“没有发生”。
- 回答下方卡片显示候选链接、模型实际得到的摘录、各来源成功/无结果/失败/超时状态。`[1]` 这类引用编号的审计只能验证编号是否存在，**不能验证推理或事实蕴含**；重要结论仍须打开原始链接核查。

### 进阶资料源：只能填写你信任的服务

管理员打开资料检索卡片下的「进阶（可选）：自建搜索源」后，可在当前浏览器保存：

- **SearXNG 地址**：实例根地址，例如 `https://searx.example.com`；必须支持 `format=json` 且允许 CORS。
- **自定义接口**：浏览器会调用 `?q=查询词&limit=N`。接口应返回 `{"results":[{"title":"…","url":"https://…","snippet":"…"}]}`；也兼容 `items`/`data` 及常见字段别名。
- **正文读取模板**：只在深入检索中、已有可信 API 摘录不足时使用。可填前缀 `https://reader.example/`，或模板 `https://reader.example/read?url={url}`。`{url}` / 拼接地址会是 percent-encoded 的目标网页 URL；前缀末尾 `/`、`?`、`&`、`=`、`:` 有语义，不能随意删掉。`#fragment` 不会随 HTTP 请求发送，模板会拒绝它。

这些地址只接受 HTTPS；仅 `localhost` / `127.*` / `::1` 的本机调试服务可用 HTTP，内嵌用户名密码的 URL 会被拒绝。**正文读取服务会收到它要读取的网页 URL**，搜索服务会收到查询词；它们的访问日志、保留政策与内容安全由管理员自行评估。不要填不可信服务，不要在 URL 中放 token/用户名/密码，更不要把秘密写进公开的 `config.json`。

进阶搜索源与默认资料源**并行交叉取样**，不是“先让自定义源独占、失败再回退”的旧逻辑。这样不能证明默认源和自定义源互相独立，但能避免单一自定义接口完全支配本轮资料。

### 保存范围与部署检查

- 本轮资料只附加给本轮模型请求，不自动进入下一轮模型上下文；但为了历史回看和引用审计，浏览器 localStorage 会随聊天记录保存查询、链接、摘要/实际摘录、日期和来源状态。Markdown 导出只列来源链接，不导出摘录正文。删除会话或清空本机数据才能移除。敏感问题不要用于检索。
- 页面内存缓存不写入 localStorage；它与上面的聊天历史不是同一件事。
- `web/public/config.json` 的 `webSearch` 字段可设置默认开关、资料条数、单请求/总超时、页面缓存 TTL、默认提供方、深入页数和严格资料块长度。`providers` 中的 `china-static` 只是启用/停用同站快照，不能配置第三方 URL 或密钥。具体字段、范围及 JSON 样例见 [README 的联网资料检索部分](../README.md)。
- 浏览器直连的第三方 API 依赖其 CORS，必须在真实用户浏览器中测试；Node 假 fetch 测试不能证明线上可用。`china-static` 同源读取 JSON，不需要源 feed 的浏览器 CORS，但 Actions 刷新仍可能因上游故障或许可变化而失败。速率限制、地区网络、CORS、服务 API 变化都会导致部分源失败。
- 远程模型模式下，浏览器仍直接请求公开 API；服务器 CSP 的 `CSP_CONNECT_SRC` 必须同时允许 SearXNG、自定义接口和正文读取服务的 origin（默认覆盖公开 API）。`china-static` 不需要把原始 feed 域名加入 CSP，因为浏览器只读本站文件；否则浏览器会拦截对应请求。服务端 `/api/config` 不下发 `webSearch`，所以远程模式使用客户端内置默认值和本机设置。

## 七、管理员信息：更正、知识库与说明

这三类信息都保存在本机，每次回答时作为**最高优先级**放进系统提示。

| 类别 | 如何添加 | 上限（每个 AI） | 如何删除 |
|---|---|---|---|
| **更正** | 发送一行 `更正：新说法`（英文冒号也可以），输入管理员密钥验证后记录 | 30 条 | “更改权限”面板 → AI 适应记录 → 更正列表中的“删除” |
| **说明（附加反馈）** | 直接发送普通文字（不含参数行）。每条说明会同时写入知识库 | 30 条 | 同上，在说明列表中删除 |
| **知识库** | 由说明自动生成（每条说明同步写入一条知识库） | 50 条 | 同上，在知识库列表中删除 |

注意：

- 更正和知识库**不会被截断**。如果它们与系统提示加起来超过窗口，发送会报错。
- 说明和知识库不随 `.ojmodel` 模型文件导出。
- 删除“新建AI”时，其适应记录会一并清除。

### 生图 AI 的更正与知识库

生图 AI（文生图）同样有更正、知识库与风格提示，只保存在本机，按生图 AI 分别记录（不随聊天 AI 的记录变化）。

- **放置位置：** 更正在最前面，其次是知识库，用户描述在中间，风格提示在末尾。
- **输入上限：** 描述（文本框内容）默认最多 4096 个 token，超过则拒绝生成。管理员可在提示词中写一行“参数：inputTokens=8192”调整，最高 16384（硬上限）。注意：这只决定何时拒绝过长的输入，不改变画面；参与生图的最多约 300 个 token（见下）。
- **分段编码：** CLIP 文本编码器每段只读取 77 个 token，其中 75 个可用。描述超过 75 个 token 时分为多段（最多 4 段，约 300 个 token）分别编码再拼接。这要求模型的 UNet 接受可变的序列长度；若某个模型不支持（例如测试用的微型模型），生成会自动改用单段（仅前 75 个 token 参与生图），并在状态栏注明。
- **不被截断：** 更正与知识库只占第一段。它们自身超过约 75 个 token 时，**拒绝生成**并提示精简，而不是静默丢弃其中一部分。中文每个字通常占多个 token。
- **描述过长：** 超过约 300 个 token 时仍会生成，但末尾被截断（风格提示最先被截掉），生成完成后的状态栏会注明截断了多少 token。
- **限制：** CLIP 不会像聊天模型那样“理解并服从”文字。这里保证的是管理员内容位于最前、完整放入、不被截断，并不保证画面一定符合更正的内容。

### 迁移到生图 AI

- 在“更改权限”面板的“跨模型迁移”中，目标可以选择生图 AI。也可以在生图页面的管理员面板底部迁移到当前生图 AI。
- 来源可以是聊天 AI 或生图 AI。聊天 AI 的**说明**迁入生图 AI 后作为知识库条目；生图 AI 的**风格提示**只能迁入其他生图 AI。
- 复制而非移动；完全相同的文字跳过；每类最多 30 条，超出的不写入并会提示。迁移更正仍需输入管理员密钥验证。

## 八、标记错误（修正某个错误说法）

1. 在某条回复的下方点击“**标记错误**”（仅管理员、仅本机模式可见）。
2. 填写**错误的说法**与**正确的说法**，输入管理员密钥，点“**验证并记录**”。
3. 正确的说法会同时作为该 AI 的更正。之后该 AI 的回答若再出现错误说法，会在回答下方提示正确说法（不会改写回答）。

标记针对**即将回答的 AI**，不是这条回复所用的 AI。

## 九、恢复与清空

- **恢复默认（单个参数）：** “更改权限”面板 → AI 适应记录 → 当前生效值旁的“恢复默认”。
- **全部恢复默认：** 同一区域的“全部恢复默认”。
- **清空某个 AI 的全部记录：** AI 适应记录中该 AI 的“清空”。会删除说明、知识库、更正、参数与变更记录，无法恢复。
- 只影响当前浏览器。普通用户看不到参数改动，但会受其影响。

## 十、导出与迁移（可选）

- **导出固化数据：** AI 适应记录中该 AI 的“导出固化数据”，导出更正与知识库，供在本机用 `training/ojtrain.py solidify` 训练（需要 GPU）。
- **跨模型迁移：** AI 适应记录上方的迁移区域，可把源 AI 中勾选的更正与知识库复制到目标 AI（复制而非移动）。
- **导出所选数据：** 可选择导出会话、说明、参数、更正、知识库与新建AI清单。

## 十一、修改默认值（需要重新构建）

默认值写在 `web/public/config.json` 中：

| 键 | 含义 | 当前值 |
|---|---|---|
| `contextWindowTokens` | 上下文窗口默认值 | 16384 |
| `slidingWindowTokens` | 滑动窗口默认值 | 4096 |
| `thinkingWindowTokens` | 思考窗口默认值 | 4096 |
| `temperature` | 温度默认值 | 0.3 |
| `maxTokens` | 最大输出长度默认值 | 16384 |
| `contextChars` | 历史字数上限（滑动窗口关闭时） | 8000 |
| `maxMessages` | 历史条数上限（滑动窗口关闭时） | 15 |

修改方法：

1. 编辑 `web/public/config.json`，修改对应的值。
2. 在项目目录运行 `npm run build`，然后重新部署网站。

允许范围定义在 `web/src/budget.js` 的 `WINDOW_LIMITS` 中，参数行的允许范围定义在 `web/src/adaptation.js` 的 `PARAM_LIMITS` 中。修改这些范围需要改代码，不能只改配置。

## 十二、常见问题

- **修改后没有生效？** 参数行与开关的改动在下一次发送时生效；如果是模型窗口变化，系统会先释放显存再重新加载，首次回答会稍慢。
- **提示“管理员信息……已超出窗口”？** 精简更正、知识库或说明，或调大当前使用的窗口（滑动窗口开启时为 `slidingWindow`，最大 20000）。
- **固定提示显示“已修改参数”，但模型没有回答？** 这是机械识别：消息中只有参数指令且不含问号，所以不调用模型。要让模型回答，请在消息中加上问题。
