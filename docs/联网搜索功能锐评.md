# 锐评：「联网资料检索」——一场没有 AI 参加的 AI 联网搜索

> 评审环境：无 API Key、无独立服务器、浏览器直连（即该功能唯一能开箱即用的形态）。
> 评审方法：60 个单测全部通过之外，用仓库自身的纯逻辑模块对真实场景做端到端重放，mock fetch 抓包取证。以下每一条刀刃都有实测输出背书。

## 总判词

**这不是搜索引擎，这是四个 CORS 友好的公开 JSON 端点，加五个每日一更的 RSS 博客，外面裹了三千行防御工事。** 工程道德满分，产品能力不及格；README 诚实地承认"这不是通用网页搜索"——这是全文最准确的一句话。

---

## 一、整个功能里最没有 AI 的，就是 AI 联网搜索

查询词的"理解"由正则完成：取第一行带问号的句子，砍到 120 字。实测：

| 用户输入 | 提取出的查询词 |
|---|---|
| `装好了环境 → 一直报 segmentation fault → 这是为什么？` | **「这是」** |
| `能帮我看看吗？→ 快排为什么在有序数组上退化到 O(n^2)` | **「能 看看」** |

第一行命中 `？` 就赢者通吃，真正的问题原文直接丢弃。于是系统郑重其事地把「这是」发给 zh.wikipedia、en.wikipedia、api.stackexchange.com、hn.algolia.com 四个端点（抓包实锤）。

2026 年了，一个跑着大语言模型的聊天产品，联网搜索的每一个环节——查什么、怎么翻、结果好不好——**模型本人的参与度为零**。没有查询改写、没有相关性反馈、没有在环重试。这等于给 F1 赛车配了一条导盲犬：模型再聪明，缰绳在正则手里。

## 二、给中文用户的"国际互联网"，是一本 30 个词的袖珍词典

中文查询跨语言的全部指望是 `TERM_GLOSSARY`——一个硬编码了"诺贝尔文学奖""并查集"等三十来个词条的字典。实测：

- `红黑树是怎么保持平衡的` → 词典翻译：**空**
- `一致性哈希是什么` → 词典翻译：**空**
- `它的` + `时间复杂度` → 词典翻译：**「它的 time complexity」**

翻译为空时，英文维基 fallback 拿着整句中文去搜 en.wikipedia（抓包：`srsearch=平衡二叉树的旋转怎么理解` 打在英文站上），而另一头的相关性过滤器再把幸存的英文结果整体枪毙——实测英文 Red–black tree、Consistent hashing 权威条目**双双被过滤为 false**。左手搜了个寂寞，右手把寂寞毙掉。所谓"英文回退"，回的是个寂寞，退的是用户。

## 三、中文整句原样快递给 Stack Overflow 和 Hacker News

抓包铁证：`api.stackexchange.com/.../q=平衡二叉树的旋转怎么理解`、`hn.algolia.com/...query=平衡二叉树的旋转怎么理解`。这两个源对中文问题的命中率无限趋近于零，但每一轮提问都会把访客 IP + 中文问题原文直送两家美国公司的日志系统，换来两条注定空手的请求。**花真金白银的隐私，买两张必输的彩票。** README 说得坦诚："不需要 API Key 不是隐私承诺"。坦诚，但坦诚不能让这趟快递变得合理。

顺带一提：Stack Exchange 匿名配额是每 IP 每天 300 次。GitHub Pages 公开站 + 校园网共享出口，一个班的学生上午就能把配额抽干——之后 SO 源天天躺在错误列表里给卡片凑数。

## 四、唯一长得像"全网搜索"的选项，默认关着，而且本来就不是全网搜索

DuckDuckGo Instant Answer 默认关闭，开了也只是"即时答案"摘要 API，不是网页索引。所以在无服务器约束下，"联网"的实际覆盖面是：

**维基百科 + Stack Overflow + Hacker News + 五个 RSS（中国政府网 / 交大新闻网 / V2EX / 阮一峰 / IT之家）**

新闻、版本发布、赛事题解、任何维基没有的实时信息——一律抓瞎。功能名叫"联网资料检索"，本质是"维基百科侧栏 + 订阅了一个技术博主的 RSS 阅读器"。装了个互联网的名字，装不下互联网。

## 五、相关性过滤：双刃剑，但刀刃永远朝着用户

`filterRelevantResults` 用 bigram 重叠打分：三个词以上必须命中两个，否则毙。实测结果：

- 英文权威条目（表述不同）→ **毙**
- HN 上"Show HN：我做了个排序可视化工具" → 面对提问"快排为什么比归并快"，**放行**，还挤进资料块占了正式编号

没有打分、没有排序，五个来源在 `interleaveByProvider` 里轮流坐庄——HN 的水帖和维基的正文一人一个坑，一视同仁地稀释。粗过滤拦住的往往是最有价值的那条，漏进的永远是最话痨的那条。

## 六、12 秒、4 路并发、总超时 12 秒——产出约 1000 字符

快速模式资料块总预算 1600 字符，扣除 120 字符免责声明头和每条约 100 字符的元数据，实测五条资料的正文合计 **1011 字符，均摊每条 202 字符**。SO 的问题摘要在 240 字符处拦腰截断，就这还要冠以 `[编号]` 请模型"引用"。深入模式 3200 字符，翻倍地少。

八秒单请求、十二秒总预算、四路并发，换回的内容量不如模型自己权重里背的多。这套超时架构防慢源防得滴水不漏，只是忘了问一句：抢回来的这点东西，值不值这十二秒。

## 七、"深入检索"的正文补充：把 Python 压成一行的压路机

`stripHtml` 把所有空白折叠成单空格。实测 SO 采纳答案经过它之后：

```
def two_sum(nums, target): seen = {} for i, n in enumerate(nums):
if target - n in seen: return [seen[target - n], i] seen[n] = i return []
```

Python 的缩进就是语义，喂给模型的"采纳答案"是一具被压路机碾过的代码尸体。**一个刷题助手，把出现频率最高的代码类证据处理成这副样子**，然后在卡片上标注"Stack Overflow 采纳答案"邀请用户信任。

## 八、隐私防线是筛子，专挑没用的地方严

- URL 里带 `password=123456` → 整次检索直接毙（合理）；
- `localStorage.setItem("password", "abc123")` → **实测照发**，查询词「我设置了 localStorage setItem password abc123 会不会有安全问题」原样外发四家第三方。

正则只认识 `password =`，不认识 `("password", "abc123")`。所谓"疑似凭据绝不外发"的承诺，只对恰好长得像 `key=value` 的凭据成立——而真会把密码写成 `=` 的人，往往也把整个工程文件贴进来了，那时 fenced code block 一样照删、查询词一样照发。防线修得庄重，执行得随机。

## 九、60 个测试全绿，全靠自导自演

`web-search.test.js` 一千一百行，fetch 全部注入 mock，**没有一个对真实 API 的集成测试**。CORS 变没变、配额还有没有、返回格式改没改，测试一概不知。而真实的全空场景实测会给用户看：

> 「没有相关结果；没有相关结果」

——文案重复了，而 china-static 那条真正有用的诊断（"尚未生成首个快照"）被 `slice(0, 2)` 挤出显示区。测试覆盖率是给代码写的，不是给用户写的。

## 十、防御工事修到了牙齿，主炮是水管

数一下排场：280 行配置校验、700 行隐私防线、3000 行测试、每日 CI 刷快照、四层 URL 清洗、逐项 CLAMP。再数一下产出：一个从正则里猜词、发给看不懂中文的接口、再被 bigram 过滤器毙掉大半、最后挤进 1600 字符提示词缝里的"资料检索"。**把碉堡修在了水井上。**

## 公道话（锐评的职业道德）

在"无 API、无服务器"的约束下，这份实现有几个同行该学的优点：**不伪造能力**（搜不到就明说，不拿模型记忆冒充搜索结果）、**失败路径全部显式**、**README 把边界写得比很多产品的文档都诚实**、prompt 注入防护和引用审计确实做了而不是贴个 sticker。约束本身把天花板钉在贴地的位置，这不是代码的错。

但正确的结论是：认清天花板之后，就该把功能叫回它的本名——"维基百科与五个订阅源的资料侧栏"，然后把力气花在刀刃上（模型在环的查询改写、对中文查询直接放弃 SO/HN、给代码保留换行的摘录、一个真实 API 的冒烟测试）。而不是用三千行 ceremonious 的防御代码，去伺候一个开箱即用时连"红黑树"都查不到的搜索。

**一句话终审：这是给 AI 配的联网搜索里，最守规矩的一个；也是守规矩守到忘了自己是干嘛用的一个。**
